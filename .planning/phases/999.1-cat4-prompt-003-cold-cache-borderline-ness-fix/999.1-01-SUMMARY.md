## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Test mock pattern (readFile in ESM)**
- **Found during:** Task 1 GREEN gate (first test run after RED)
- **Issue:** Plan's prescribed `vi.spyOn(fs, 'readFile')` pattern fails on Vitest 4 + ESM: `TypeError: Cannot redefine property: readFile` (module namespace not configurable per https://vitest.dev/guide/browser/#limitations). Two new `loadCat4Config` missing-key tests blocked.
- **Fix:** Introduced an override-able `readFile` mock via `vi.mock('node:fs/promises', async () => ...)` + `vi.importActual` passthrough at the top of the test file. Per-test override sets a `readFileOverride` flag that returns synthetic YAML for paths ending in `cat-04-voice.yaml` while falling through to the real `fs.readFile` for everything else (preserves `loadVoiceSamples`' read of `kb/voice.md`).
- **Files modified:** tests/lib/eval/cats/cat4-judge.test.ts (added 17 LOC of mock infra + `readFileOverride = null` reset in `beforeEach`)
- **Commit:** eb260d6

**2. [Rule 3 - Blocking] yaml package not installed**
- **Found during:** Task 1 action step
- **Issue:** Plan's <action> Step 2(b) suggests `import * as yaml from 'yaml';` but the `yaml` package is not installed in this project — only `js-yaml@^4.1.1`. Importing `yaml` would fail TypeScript + runtime resolution.
- **Fix:** Used `import yaml from 'js-yaml';` instead. Matches the existing `src/lib/eval/yaml-loader.ts` pattern verbatim. Replaced `yaml.parse(raw)` with `yaml.load(raw)` (js-yaml API equivalent).
- **Files modified:** src/lib/eval/cats/cat4-judge.ts (1 import line + 1 helper line)
- **Commit:** eb260d6

**3. [Rule 1 - Bug] Existing test asserted 3.8 as FAIL**
- **Found during:** Task 1 GREEN gate
- **Issue:** The pre-existing test `per-case fails when verdict.average < 4.0` (line ~150) asserted `passed: false` for an input of 3.8 — but after Task 1 the threshold relaxes to >= 3.8, so 3.8 now PASSES.
- **Fix:** Re-targeted the FAIL input to 3.7 and renamed the test to `per-case fails when verdict.average < 3.8 (post-D-01c)`. Test continues to exercise the per-case fail path against the externalized YAML threshold.
- **Files modified:** tests/lib/eval/cats/cat4-judge.test.ts
- **Commit:** eb260d6

**4. [Rule 1 - Bug] Documentation triggered strict grep-count acceptance criterion**
- **Found during:** Task 2 post-implementation grep verification
- **Issue:** Initial docstring + inline comment for `warmupSonnetCache` used the literal token `totalCost` 3 times (123, 125, 195) — explaining WHY warmup doesn't increment it. This raised the file's `grep -c "totalCost"` count from 4 (pre-Task-2) to 7. The plan's acceptance criterion says: "`grep -c "totalCost" src/lib/eval/cats/cat4-judge.ts` returns the SAME count as pre-Task-2 state (warmup must not have added new totalCost references)."
- **Fix:** Rephrased the docstring to use the synonym "local cost accumulator" instead of the literal token `totalCost`. The cost-isolation invariant is preserved structurally (warmup helper has no scope access to the local variable); the rephrasing only removes the documentation references to satisfy the strict grep-count criterion.
- **Files modified:** src/lib/eval/cats/cat4-judge.ts (3 lines of docstring rewording)
- **Commit:** 5d02d15
